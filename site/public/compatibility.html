Compatibility

Honestly tiered: what Wavr does with hardware you probably already have, and what each extra piece of hardware buys you. Nothing here is required to start.

Tier 1 — runs today, no extra hardware

Any Windows, macOS or Linux machine. Windows needs nothing else installed; macOS and Linux need Python 3.11 or newer.

PlatformStatusNotes
Windows 10/11SupportedA real installer, unsigned — SmartScreen warns once. Download it here.
macOSSupportedRun from source with python3; no packaged installer yet.
Linux (desktop, laptop, or Raspberry Pi)SupportedOne-command install script (not yet run on real hardware); Docker also works.

At this tier, network scanning and Bluetooth presence work with nothing plugged in beyond what the machine already has. Bluetooth has one condition worth knowing in advance: it only starts contributing once you have told Wavr which device belongs to whom, so on a brand-new Space the network scan is doing all of the work until you register something. This is the fusion engine's floor, not a stripped-down mode: it's the same FusionEngine every other tier uses, just fed fewer sources.

Tier 3 — a dedicated, always-on Core

The same code, running on a small box that stays on so the dashboard is a bookmark instead of something you start by hand.

Raspberry Pi / mini PC

Recommended: the Linux install script (install.sh), which can offer a systemd autostart unit so the dashboard survives a reboot. Already run everything in Docker, or managing a NAS? ./scripts/wavr-docker.sh up works too (network_mode: host, access from other devices over an SSH tunnel). See Install.

A GPU-equipped box

For camera detection at scale, a machine with a GPU runs the YOLO model far more comfortably than a Pi's CPU. The base Docker image is lean (no camera/GPU dependencies); the GPU variant is a documented follow-up, not shipped as a ready image yet.

Windows Docker Desktop

Not the appliance path Docker Desktop's network model doesn't support network_mode: host the way Linux does. On Windows, use the Windows installer instead and save Docker for a real Linux box.

Phones and tablets

Usually a phone is a view that pairs to a Core. It can also be the Core itself — see the last card.

Android

Works today Pair a browser to a Core over local HTTPS, no install required, or install the companion app from Download for a full-screen, app-like view without the "Add to Home Screen" step.

iOS / iPadOS

Works today Same route via Safari, "Add to Home Screen" for a full-screen view.

Android kiosk launcher

Source only, unsigned, experimental An always-on ambient panel launcher exists in the repo as a Gradle project. It hasn't been signed for general use; treat it as a reference for now.

Android as a Core

Source only, unsigned The same Gradle project builds a second app that embeds CPython and runs the real Core on the phone — not a reduced copy, the same code the desktop runs. It builds and the Core answers, but it has never been run on a physical handset: it has no first-run setup screen yet, and battery behaviour, surviving Doze overnight and restarting after a reboot are all unmeasured. No Play Store release; do not install it today. See Download for the current build status.
