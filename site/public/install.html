Install Wavr, every platform

The full list: Windows, macOS, Linux, Raspberry Pi, Docker, Android and iOS, plus building from source. Looking for the quick path instead? See Download for Windows and Android.

Two phases, so this page is honest about what it knows. Phase A (below) is a guess about your platform from your browser, nothing more. Phase B, the real scan of what your machine can actually do (cameras, Bluetooth, a serial port for a radar sensor), only happens locally after you install Wavr and never touches this website.

Recommended for you

All platforms

Windows

Real installer, no Python needed

A genuine double-click installer: one file, nothing else to install first. It bundles the whole Core (backend, database, dashboard) into its own executable, so there is no separate Python to find or install. That requirement is gone. Installed, it's three files: wavr-desktop.exe (the window/tray shell), wavr-core.exe (the bundled Core), and an uninstaller.

The installer is unsigned. There is no code-signing certificate yet, so Windows SmartScreen will warn that it's from an unknown publisher when you run it. That's expected, not a sign something is wrong. Still, don't just click through blindly: check the download's SHA-256 against the one published with the release before you trust it.

Not published yet No release has been cut, so there is nothing to download here today. Once one exists, this page shows a Download button for it automatically, with no change needed here. Until then, see Advanced: install from source, or the developer bootstrap under Advanced: install.ps1.

macOS

No packaged installer yet

There's no notarized macOS build published yet. Today, Wavr runs from source:

  1. Install Python 3.11 or newer (brew install python@3.11, or from python.org).
  2. Get the code: clone https://github.com/augbastos/wavr.git.
  3. In Terminal: 
    cd wavr/backend
pip3 install -e .[dev]
cd ..
python3 -m wavr.serve
  4. Open http://127.0.0.1:8000. That's your dashboard, loopback-only by default.

Want a real app window? See Advanced: build the desktop app below. Its LAN/multi-device HTTPS trust is currently wired up for Windows only; the default loopback mode is identical on every platform.

Linux (incl. Raspberry Pi)

Installer script, not yet run on real hardware

There's no .deb or .AppImage yet, but there is a script that does the whole job in one command: find Python, set Wavr up in its own folder, start it. It never runs sudo itself.

  1. Download install.sh (not on the public repository yet — see the repository) from the repository.
  2. Run it: 
    sh install.sh
  3. It prints the dashboard address once it's up, usually http://127.0.0.1:8000: open that in a browser on the same machine (there's no auto-open, since a Pi is often headless).

It installs into ~/.local/share/wavr (override with --dir), needs Python 3.11 or newer (it prints your distro's exact install command if you don't have it), and works on Debian/Ubuntu/Raspberry Pi OS, Fedora, Arch and Alpine. Running it again upgrades in place; --uninstall removes it and leaves your data alone. It can offer a systemd --user unit for autostart at login, but only if you say yes.

Not yet run on real Linux or Raspberry Pi hardware. It's POSIX-clean and was logic-tested (argument parsing, the download-and-extract path, uninstall) on this project's own dev machine, but nobody has run it end to end on an actual Linux box or a Pi yet. If a distro's package name is wrong or a step behaves differently on yours, that's the most likely place to look; treat it as reviewed, not field-proven. Full status: docs/INSTALL.md (not on the public repository yet — see the repository).

Prefer to install by hand, or run it in Docker instead? See Advanced: install from source or Advanced: Docker.

Android

Not published yet No Android app has been published here today. Pair a browser instead, with no install at all:

Or pair a browser, with nothing installed at all:

  1. Set up a Core first: see Windows, macOS or Linux above.
  2. On the Core, open Settings and turn on "Let other devices connect". It asks you to confirm, because it is the one switch that takes Wavr off its own machine.
  3. Scan the QR code the Core shows you. It carries the address and the Core's certificate fingerprint, so nothing has to be typed and your phone can tell it reached the right machine.
  4. Confirm the pairing on the Core's screen.
  5. Add the page to your home screen for a full-screen, app-like view.

This browser route works on any phone or tablet, installed app or not, and is the only route on iOS/iPadOS (see below).

iOS / iPadOS

Works today, no app to install

Same idea as Android: there's no App Store app, and none is needed. Open your Core's address in Safari, pair once, then use the Share sheet's "Add to Home Screen" for a full-screen companion view.

  1. Set up a Core first: see Windows, macOS or Linux above.
  2. Turn on multi-device pairing on the Core and note its LAN address.
  3. Open that address in Safari and accept the one-time certificate trust warning (it's your own Core's self-signed certificate).
  4. Enter the pairing code shown on the Core, then add it to your home screen.

Docker (Linux / NAS / appliance)

For a NAS, or if you already run everything in Docker. The repo ships a lean Dockerfile and docker-compose.yml (network scan, Bluetooth, fusion; no camera/GPU support in the base image), plus a small wrapper script. Run this from inside a checkout:

git clone https://github.com/augbastos/wavr.git
cd wavr
./scripts/wavr-docker.sh up      # builds if needed, waits for /healthz, prints the URL

wavr-docker.sh logs follows the container log, status shows docker compose ps, down stops and removes it. It's a thin wrapper around docker compose up -d --build; running that directly works too.

The dashboard is baked into the image (backend/Dockerfile copies frontend/ in), so GET / serves the real dashboard, not just the API. It's bound to 127.0.0.1 using network_mode: host, which keeps Wavr's own loopback-only guard intact. Reach it from another device by tunnelling over SSH (ssh -L 8000:127.0.0.1:8000 user@host), not by exposing the port directly.

Windows/macOS caveat: Docker Desktop's networking model doesn't support network_mode: host the same way Linux does. The wrapper warns (doesn't block) if it detects a non-Linux host; for the actual running service on Windows or macOS, use the install script or source route for that platform instead and save Docker for a real Linux box.

No image is published to a registry yet: this builds locally, there's nothing to docker pull.

Install from source (any platform)

For contributors, or if none of the scripts above fit. This is the same workflow this repo's own CI uses:

git clone https://github.com/augbastos/wavr.git
cd wavr
pip install -e "backend[dev]"
python -m wavr.serve                   # loopback 127.0.0.1:8000
python -m pytest backend/tests -q      # full suite, all hardware mocked

On Windows, scripts\wavr-desktop.ps1 does the same thing and also opens your browser once the backend answers. Full detail: docs/INSTALL.md (not on the public repository yet — see the repository).

Windows: install.ps1 (developer bootstrap)

Before the self-contained installer above existed, this repo's Windows route was a script that finds a Python 3.11+ already on your machine and sets up an editable checkout. Still useful if you want to hack on Wavr rather than just run it, but unlike the installer above, it does need Python installed first.

  1. Download install.ps1 (not on the public repository yet — see the repository) from the repository.
  2. Run it: 
    powershell -ExecutionPolicy Bypass -File .\install.ps1

It installs an editable checkout into %LOCALAPPDATA%\Wavr, needs Python 3.11 or newer (it tells you where to get it if you don't have it), and running it again upgrades in place. -Uninstall removes it and leaves your data alone.

Build the desktop app (and its installer) from source

The Windows installer above is a Tauri v2 shell wrapped around a PyInstaller-frozen Core. Building it yourself, instead of waiting for a published release, needs Rust, Node.js 18+, and Python 3.11+; Python is only needed to freeze the Core once, the result of that step doesn't need it.

  1. Install Rust (on Windows this also needs the Microsoft C++ Build Tools) and Node.js 18+.
  2. Freeze the Core into a single executable: 
    pip install pyinstaller
pyinstaller desktop/sidecar/wavr-core.spec --distpath desktop/sidecar/dist
# rename the result to the target triple Tauri expects, e.g.
# wavr-core-x86_64-pc-windows-msvc.exe, and place it in desktop/src-tauri/binaries/
  3. Build the shell: 
    cd wavr/desktop
npm install
npm run icon      # generates src-tauri/icons/* from ../frontend/icon.svg, once
npm run dev       # dev build, live-reloads
# or: npm run build   # produces the installer under src-tauri/target/release/bundle/

Skip step 2 to run against a plain Python install instead: the shell falls back to python -m wavr.serve when no bundled Core is present, the same as before this existed. More detail (some of it predates the bundled Core): desktop/BUILD.md in the repository.
